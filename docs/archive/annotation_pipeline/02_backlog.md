# Samsung Notes → Obsidian 백로그

작성일: 2026-10-08 · 관련 문서: [개발 계획](01_plan.md) · [검증 계획](03_verification.md)

## 1. 관리 원칙

첫 버전은 PDF 주석 추출과 사용자 글을 보존하는 갱신에 집중한다. 아래 항목은 구현 약속이 아니라 후속 후보이며, 사용자와 합의한 보류 항목과 원안의 장기 후보를 구분한다. 우선순위는 개발 제안이며 실제 샘플과 사용 경험에 따라 조정한다.

외부 AI API는 현재 사용 금지 정책이다. AI 기반 후보를 구현하려면 해당 정책부터 별도로 재합의해야 한다.

## 2. 명시적으로 보류한 기능

| ID | 기능 | 우선순위 제안 | 시작 조건 | 완료 기준 |
| --- | --- | --- | --- | --- |
| B01 | PDF에서 글자·영역을 직접 선택하는 인용 확인 UI | 중 | 복사·붙여넣기 확인의 불편이 확인됨 | 페이지를 보며 선택하고 출처·인용을 저장 가능 |
| B02 | 별도 로컬 웹 확인 화면 | 중 | 확인 대기량이 많아 Obsidian만으로 관리 어려움 | 목록·입력·상태가 기존 확인 데이터와 일치 |
| B03 | 필기 부분만 배경과 함께 잘라 표시 | 중 | 전체 페이지 이미지가 읽기를 방해함 | 필기 누락 없이 문맥 포함, 원래 페이지로 연결 |
| B04 | 페이지 추가·삭제·재배열 대응 | 중 | 실제 사용자가 해당 편집을 함 | PDF 페이지와 노트 페이지를 구분해 기존 사용자 글·링크 유지 |
| B05 | 스캔 PDF OCR | 낮음 | 스캔 자료 비중이 실사용을 제한함 | 별도 인식 품질 평가 및 오인용 방지 관문 통과 |
| B06 | 폴더별 자동 MOC | 낮음 | 추출·갱신 안정화 후 탐색 수요 확인 | 생성 내용과 사용자 내용 충돌 없이 목록 갱신 |
| B07 | 자동 태그·상위 링크 | 낮음 | 분류 규칙을 실제 사용자와 합의 | 결정적 규칙과 사용자 수정 보호를 갖춤 |

## 3. 샘플 결과에 따른 조건부 작업

이 항목은 필요해지면 첫 버전의 선행 작업이 될 수 있다. 필수 실패 처리를 backlog로 미루는 의미가 아니다.

| ID | 작업 | 발생 조건 | 조치 |
| --- | --- | --- | --- |
| C01 | 펜 밑줄 추출 개선 | 펜 표시가 90% 수정 불필요 기준 미달 | 우선 수동 확인으로 한정, 사용량과 전체 수동 부담 보고 후 개선 여부 결정 |
| C02 | Parser 기능 보완 | 기존 파서가 필요한 객체/좌표를 제공하지 못함 | 최소 기능만 보완하고 독자 전체 재구현은 재검토 |
| C03 | 원본 PDF 확보 대안 | sdocx에서 온전한 PDF를 회수하지 못함 | 구현 중단 지점으로 기록, 별도 PDF 지정 허용 여부 재합의 |
| C04 | 여러 PDF/일반 노트 지원 | 실제 샘플에 해당 구조가 등장 | MVP에서는 이유를 표시하고 보류, 식별·출력 단위부터 새로 설계 |
| C05 | 성능·저장 최적화 | 실제 노트 규모에서 처리 시간/용량 과다 | 측정 후 변경 페이지 재처리·자산 공유·캐시 순으로 검토 |

## 4. 원안의 장기 후보

| ID | 후보 | 현재 판단 |
| --- | --- | --- |
| L01 | Excalidraw 변환 | 필기 편집 수요가 생길 때 검토 |
| L02 | 손필기 OCR | 현재는 이미지 보존으로 충분. 별도 품질 검증 필요 |
| L03 | 의미 기반 링크·주제·태그 추천 | 현 범위 외. AI API 미사용 정책을 임의로 바꾸지 않음 |
| L04 | 일반 텍스트 노트의 폭넓은 서식 변환 | PDF 주석 수집 안정화 후 검토 |
| L05 | 자산 중복 제거 | 동일 PDF의 별도 노트 정체성을 유지한 상태에서만 검토 |
| L06 | Windows 트레이·설정 GUI·상태 대시보드 | MVP 바로가기와 결과 요약으로 부족할 때 검토 |
| L07 | Obsidian Community Plugin | 파일 기반 방식의 한계가 실제로 확인된 경우 검토 |
| L08 | Obsidian → 삼성노트 역방향 동기화 | 별도 프로젝트 수준의 설계 필요. 첫 버전은 단방향 |
| L09 | 세밀한 색상·정렬·글꼴 등 서식 | 원문 의미와 인용 정확도보다 우선하지 않음 |

## 5. 후순위로 보내면 안 되는 항목

- 원본 PDF 회수와 페이지 대응의 실제 검증.
- 인용 오류 검출 및 수동 확인 상태 관리.
- 사용자 글 보존, 자동 영역 수정 감지, 마커 훼손 시 중단.
- 원본 삭제·폴더 이탈·소스 일시 장애 구분.
- 최신 원본 및 30일 버전 이력.
- UUID 중복·식별 실패에서 임의 병합하지 않는 처리.
- 파일 쓰기 실패·동시 편집·중복 실행에서 기존 결과 보존.

## 6. 항목 승격 양식

```markdown
### Bxx / 제목
- 실제 불편 또는 실패 사례:
- 샘플/빈도:
- 범위 변경:
- 기존 정책과 충돌 여부:
- 구현 후보:
- 완료 및 검증 기준:
- 결정: 보류 / 채택 / 폐기
```

실제 사용자의 작업을 막는 정도, 발생 빈도, 구현 부담을 함께 보고 순서를 정한다.

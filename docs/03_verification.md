# 필기 포함 PDF 변환·갱신 검증 계획

갱신일: 2026-10-14 · 상태: 사용자 선택 반영 / 폴더형 입력과 새 파이프라인 검증 미실행.

관련 문서: [계획](01_plan.md) · [구조 조사](05_structure_research.md)

## 1. 검증 목표

삼성노트에 보이는 노트 내용이 PDF에 빠짐없이 재현되고, 백업 변경 후 해당 출력만 안전하게 갱신되는지 확인한다. 잘못된 최신본/노트 대응, 내용 누락, 기존 파일 손실을 우선적으로 막는다.

기존의 최소 50개 표시·90% 자동 인용 성공률은 이 파이프라인의 합격 기준이 아니다. 새 기준은 내용 재현, 등록/갱신 동작, 실패 복구다. 구현되지 않은 시나리오는 미실행으로 남긴다.

## 2. 준비할 입력과 비교 기준

- 실제 Windows 백업 폴더의 sdoc/wdoc/SQLite 구조와 동일 노트 변경 전후 폴더/이벤트 기록. 필요한 공유 자산과 DB 동반 파일의 존재 여부도 확인한다.
- 삼성노트 화면 또는 삼성노트 자체 PDF 내보내기 결과. 노트 전체의 페이지 순서와 객체를 비교할 수 있어야 한다.
- 기존 JSSC/MSD/PSS 샘플: PDF 배경, 필기, type 7 도형, 삽입 PNG, PDF 없는 중간 페이지, 90도 회전 사례.
- 실제 타이핑 메모/변환 텍스트가 들어 있는 추가 샘플. 기존 세 샘플에는 비공백 본문 문장이 없었음.
- 표시 수정·삭제, 페이지 추가·삭제·순서 변경, 파일 이름 변경/이동의 전후 사례.

샘플 원문을 공개 저장소에 넣지 않는다. 실제 Windows와 Obsidian 버전, 백업 경로 종류, 변환기 버전과 선택 정책을 실행 기록에 남긴다.

## 3. Gate A — 백업 입력과 식별

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| A01 | 삼성노트 자체 기능으로 폴더형 백업 | 실제 계층, sdoc/wdoc/SQLite의 역할과 노트별 데이터 묶음을 확인 |
| A02 | 같은 노트 수정 후 재백업 | 같은 경로 수정/새 버전 생성 규칙을 관측하고 동일 노트 대응 가능 |
| A03 | 제목이 같은 서로 다른 노트 | 하나의 출력으로 합쳐지지 않음 |
| A04 | 페이지·미디어·메타데이터의 순차 갱신 | 한 파일만 안정됐다고 진행하지 않고 노트 입력 묶음의 일관성 확인 뒤 게시 |
| A05 | 지원하지 않는 입력 | 읽을 수 없는 포맷을 성공 처리하지 않고 사유 표시 |
| A06 | 공유 SQLite 변경 | 노트 목록/참조를 재확인해 영향 노트를 연결. 무관한 노트 PDF는 다시 쓰지 않음 |
| A07 | DB 사용이 필요한 입력 | 쓰기 중에도 일관된 읽기/스냅샷 확보. 필요한 WAL 등 상태를 빠뜨리지 않고 원본 DB에 쓰지 않음 |

폴더형 입력은 사용자 관측으로 확인했지만 동일 경로 갱신은 아직 추정이다. 재백업을 직접 관측하기 전 식별 규칙을 검증 완료로 표시하지 않는다. 기존 SDOCX 샘플이나 그 압축 해제 폴더만으로 실제 Windows 백업과 호환된다고 판정하지 않는다.

## 4. Gate B — 단일 노트 PDF 재현

| ID | 확인 내용 | 통과 조건 |
| --- | --- | --- |
| B01 | PDF 열기·페이지 순회 | 파일이 열리며 노트 페이지 수/순서/크기가 비교 기준과 일치 |
| B02 | 원문 배경과 필기 | 필기 위치, 색, 굵기, 투명도, 레이어 순서가 내용 해석에 지장을 주지 않음 |
| B03 | 동그라미·화살표·도형 | 중요한 도형 누락 없음. MSD type 7 사례 포함 |
| B04 | 이미지 및 PDF 없는 페이지 | PSS 중간 이미지/필기 페이지가 포함되고 내용이 잘리지 않음 |
| B05 | 타이핑/변환 텍스트 | 글자 누락·깨짐·잘못된 줄 배치가 없음 |
| B06 | 회전·크롭·배율 | PSS 90도 회전과 서로 다른 페이지 크기에서 배치 정상 |
| B07 | 페이지 추가·삭제·재배열 | 변경된 노트 전체 순서가 결과 PDF에 반영 |
| B08 | 빈 페이지/placeholder | 실제 사용자 페이지를 자동으로 없애지 않음. 제외에는 근거 기록 |
| B09 | 미해석 객체 | 누락을 성공으로 숨기지 않으며 정식 출력 교체를 보류 |
| B10 | 확대 가독성/크기 | 실제 읽기 배율에서 사용할 수 있고 PDF 크기·변환 시간을 기록 |
| B11 | 원래 PDF 텍스트 검색·선택 | 필기 합성 후에도 여러 페이지의 실제 검색·선택/복사가 가능하고 원래 내용이 유지 |

원래 텍스트 PDF의 검색·선택 유지는 필수 합격 조건이다. 전체 페이지를 이미지로 바꿔 외관만 보존한 결과는 통과시키지 않는다. 필기/이미지 합성 후에도 텍스트 선택을 방해하지 않는지 실제 Obsidian에서 확인한다. 스캔 원본이나 미변환 손필기에 새 검색 기능을 만드는 OCR은 요구하지 않는다.

비교 기준 없이 PNG/PDF가 생성됐다는 사실만으로 Gate B를 통과시키지 않는다. 아직 없는 도형 렌더링을 지원 완료로 기록하지 않는다.

## 5. Gate C — 등록과 폴더 감시

자동 등록/수동 선택 등록을 제공하고 등록 후에는 모두 자동 갱신하는 정책으로 검증한다.

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| C01 | 자동 등록 모드의 기존/신규 노트 | 지정 범위에서 노트 단위를 발견해 노트별 PDF 생성. DB/미디어마다 PDF를 만들지 않음 |
| C02 | 선택 등록 모드 | 선택한 노트만 PDF 생성, 미등록 노트 이벤트로 출력하지 않음 |
| C03 | 등록된 노트 관련 파일의 수정 | 등록 방식과 관계없이 같은 연결된 PDF를 최신본으로 갱신 |
| C04 | 같은 노트 재import/관련 파일의 중복 이벤트 | 중복 PDF나 중복 변환 작업이 누적되지 않음 |
| C05 | 내용이 같은 백업 재쓰기 | PDF 내용/수정 시각을 불필요하게 다시 쓰지 않음 |
| C06 | 짧은 시간에 연속 저장 | 쓰기 중 파일을 잡지 않고 최종 안정본으로 수렴 |
| C07 | 변환 중 추가 수정 | 이전 스냅샷을 최신 성공본으로 게시하지 않고 새 버전 처리 |
| C08 | 프로그램 중지 중 백업 변경 | 재시작 재검색에서 놓친 변경 처리 |
| C09 | 백업 폴더 일시 접근 불가 | 삭제로 오판하지 않고 접근 회복 후 재검색 |
| C10 | 파일 이름 변경/이동 | 확실한 연결 또는 수동 재연결. 잘못된 PDF 교체 없음 |
| C11 | 소스 삭제 | 기존 PDF 유지, 소스 없음 상태로 갱신 중지 |

## 6. Gate D — 출력 보호와 실패 복구

| ID | 시나리오 | 통과 조건 |
| --- | --- | --- |
| D01 | 변환/임시 파일 쓰기 실패 | 마지막 정상 PDF가 그대로 열림 |
| D02 | 교체 직전 또는 도중 종료 | 손상된 최종 PDF를 남기지 않고 재시작 시 상태 대조 가능 |
| D03 | PDF가 열려 있거나 동기화 앱이 잠금 | 교체 실패 후 기존 PDF 유지, 잠금 해제 후 재시도 |
| D04 | 기존 사용자 파일과 이름 충돌 | 사용자 파일을 덮어쓰지 않고 충돌 안내 |
| D05 | 성공 상태 저장 실패 | 다음 실행에서 실제 파일과 상태를 대조하고 안전하게 복구 |
| D06 | 수동/자동 처리 동시 요청 | 같은 출력에 동시에 쓰지 않음 |
| D07 | 원본 보호 | 입력 백업 파일이 변환 전후 변경되지 않음 |

현재는 열람용 사본 정책이므로 등록된 생성 PDF를 같은 경로로 자동 교체하는 동작을 확인한다. 기존의 별도 사용자 파일 충돌 방지는 D04로 검증한다. PDF++ 등에서 추가한 수정/주석의 보존·백업·충돌 해결은 [백로그 B10](02_backlog.md)이며 첫 버전 통과 기준에 포함하지 않는다.

## 7. Gate E — 실제 Windows/Obsidian 사용

1. Windows에서 프로그램을 직접 실행해 실제 백업 폴더와 Vault 접근을 확인한다.
2. 노트를 최초 등록하고 Obsidian에서 필기 포함 PDF를 연다.
3. 삼성노트 내용을 수정하고 실제 백업이 생길 때까지 기다린다.
4. 대응 PDF가 갱신되고 Obsidian에서 새 내용을 읽을 수 있는지 확인한다. 필요한 새로고침 동작도 기록한다.
5. 프로그램 중단/재실행, 잠금 실패 한 번을 거쳐 기존 PDF와 최신 갱신이 보존되는지 확인한다.

WSL에서 연구 스크립트가 실행된 사실을 Windows 감시기/파일 잠금 검증으로 대체하지 않는다. PDF 페이지 링크는 페이지 재배열 후 다른 내용을 가리킬 수 있다는 한계를 사용 흐름에 반영한다.

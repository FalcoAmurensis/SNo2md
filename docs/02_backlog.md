# 필기 포함 PDF 연동 백로그

관련 문서: [계획](01_plan.md) · [검증](03_verification.md)

## 1. 원칙

첫 버전은 Windows의 삼성노트 폴더형 백업을 감시해 노트 전체를 PDF로 생성·갱신하는 데 집중한다. 아래 후보는 구현 약속이 아니다. 새 계획과 맞지 않는 과거 인용 추출 백로그는 [보관본](archive/annotation_pipeline/02_backlog.md)에서 확인한다.

## 2. 현재 계획의 선행 작업

다음은 선택 기능으로 미루면 안 된다.

- 실제 sdoc/wdoc/SQLite의 역할, 노트별 파일/공유 자산 연결, 동일 경로 갱신 가정 확인.
- 필기·도형·이미지·노트 텍스트 및 PDF 없는 페이지의 출력 보존.
- note 메타데이터 파싱 실패와 type 7 객체 누락 처리.
- 확정 정책 구현: 원래 PDF 검색·선택 유지, 자동/선택 등록 후 자동 갱신, 열람용 PDF 자동 교체, Windows 직접 실행.
- 여러 파일이 따로 갱신되는 동안 입력 묶음의 일관성 확보. DB가 필요하면 읽기 전용 스냅샷 방식 확인.
- 미완성 백업, 연속 이벤트, 실행 중 변경에서 마지막 정상 PDF 보존.
- 소스→출력 대응, 기존 사용자 파일 충돌 방지, 소스 장애와 삭제 구분.
- 실제 실행 환경과 Obsidian에서 PDF 생성·교체 검증.

## 5. PDF++ 등 직접 수정 지원 시 검토할 범위

현재 PDF는 열람용 생성 사본이며 소스 변경 때 자동 교체한다. 사용자는 향후 PDF++ 같은 기능으로 수정하는 경우를 고려하도록 요청했다. 해당 기능을 도입하기 전에 다음을 조사하고 정책을 합의한다.

- 실제 수정/주석이 PDF 내부, Markdown 또는 다른 파일 중 어디에 저장되는지 확인한다. 플러그인 이름만으로 저장 방식을 가정하지 않는다.
- 마지막 생성 PDF, 삼성노트 최신 입력, 사용자가 수정한 출력 사이에서 무엇이 바뀌었는지 구분한다.
- 재변환 전 버전 보관과 복원, 사용자 수정 보존, 충돌 시 덮어쓰기 보류/해결 방법을 정한다. B01과 함께 검토한다.
- 페이지 추가·삭제·재배열 뒤 주석과 페이지 링크를 어떻게 대응할지 결정한다. 잘못된 위치로 조용히 옮기지 않는다.
- Vault 동기화나 PDF 편집 중의 동시 쓰기/잠금 상황을 포함한다.

완료 기준은 삼성노트 수정과 출력 측 수정이 함께 발생해도 사용자 주석을 잃지 않고, 충돌을 드러내고 복원할 수 있는 것이다. 이것을 삼성노트로 역방향 동기화하는 B09와 동일 기능으로 취급하지 않는다. 첫 버전에 자동 병합을 추가하지 않는다.

## 6. 범위 변경 기록

후보를 채택할 때 실제 불편/샘플, 변경할 동작, 기존 출력·원본에 미치는 영향, 완료 기준을 기록한다. 외부 AI API 미사용 정책은 유지한다.
